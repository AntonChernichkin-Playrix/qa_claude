# Пример состава декомпозиции: «IDL. Проверка по ТЗ Remastered»

Реальная декомпозиция из Asana (`1217364044415843`). Нумерация оставлена как в Asana, отсюда пропуски.

**Здесь только состав: названия блоков, их порядок и решения об объединении.** Проверки айдлера не приводятся — механика у каждой фичи своя, содержимое блоков выводят из ТЗ. Формат тела задачи — в [format.md](format.md), состав основных блоков — в [template-blocks.md](template-blocks.md).

Пример **устарел в одном месте**: визуал в нём размазан по блокам HUD, окон и иконки — сейчас он собирается в один блок «Проверка графики и визуала фичи».

## Что перенять из этого состава

| Наблюдение | Вывод для новой фичи |
|---|---|
| Механика фичи — 13 блоков, остальное пришло из шаблона | Основная работа по ТЗ — середина списка; каркас берётся готовым |
| Четыре окна фичи собраны в один блок 25 | Логически связанное, проверяемое одним прогоном, — объединять |
| Один раздел ТЗ «Логика завершения» дал три блока (20, 21, 22) | Дробить только при разных условиях входа |
| «Окно дороги наград» вынесено отдельно (19) | Своя механика — расчёт и выдача наград по этапам. Только это оправдывает отдельный блок для окна |
| Визуал размазан по блокам HUD, окон и иконки | Так больше не делать: весь визуал — один блок «Проверка графики и визуала фичи» |
| Блоков про просмотры и чек-листы здесь нет | Так и надо: в состав декомпозиции они не входят |

Правила объединения и дробления целиком — в [SKILL.md](../SKILL.md), раздел «Как резать ТЗ на блоки».
